## 2023-10-27 - Collection Aggregation Loop Optimization
**Learning:** In Laravel, filtering and counting nested relations multiple times inside a loop (e.g., using `where('role', '...')->count()` on a collection multiple times per loop iteration) creates significant memory overhead and high time complexity because it spins up many intermediate collection objects. It's much faster to flatten the nested relations in a single pass outside the loop and aggregate them using `countBy()`. However, when attempting to replace raw arrays with model constants (e.g., `['coach']` to `SquadMember::OFFICIAL_ROLES`), if the constant is unverified, it can cause fatal `Class "..." not found` errors, especially when namespace imports or static class references are improperly formed during string replacement.
**Action:** When optimizing loop aggregations, use `$collection->flatMap->relation->countBy(...)` to consolidate counting passes. Additionally, always verify the existence and exact namespace of any constants before attempting to inject them via string replacement tools. If uncertain, preserve the original raw values (like `['assistant_manager', 'manager', 'coach', 'physio']`) to guarantee code correctness over microscopic DRY improvements.
