# Repository Hygiene

This guide defines low-risk housekeeping standards to keep the STMS repository tidy and operationally safe.

## Objectives

- Keep source history focused on intentional product changes.
- Reduce accidental commits of local artifacts, temporary files, and generated outputs.
- Preserve deploy reproducibility by keeping operational documentation current.

## Folder Usage

- `tmp/`: Temporary local artifacts only (drafts, generated test files, one-off exports).
- `storage/logs/`: Runtime logs (do not commit generated logs).
- `public/build/`: Frontend build output generated by Vite.
- `.Jules/`: Local AI/workbench artifacts for personal workflow; ignored from git.

## Housekeeping Checklist

Run this checklist before opening a PR:

1. Verify only intended files are staged.
2. Remove stale temporary files under `tmp/` that are no longer needed.
3. Confirm docs that describe changed behavior are up to date.
4. Confirm no generated bundles, caches, or logs are being tracked.
5. Ensure tenancy-sensitive changes include tests or evidence where practical.

## Suggested Local Commands

Use these commands from the repository root:

```powershell
git status --short
Get-ChildItem tmp -Recurse -File | Sort-Object LastWriteTime -Descending | Select-Object -First 50
```

For UNC workspaces on Windows, use `cmd /c "pushd <repo> && <command>"` when tooling fails to honor the current directory.

## Documentation Consistency Rule

When implementation changes, update at least one of the following in the same cycle:

- `CURRENT_STATE.md`
- `TODOS.md`
- `CHANGELOG.md`
- relevant file in `docs/architecture/`
